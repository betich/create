# Stack: Cloudflare (cheap)

Workers for the API, D1 for data, R2 for files, and Pages for the SPA. It runs within the free tier until the product proves itself.

```
apps/web/        vite + react → Cloudflare Pages
apps/api/        worker: hono (or elysia with its cloudflare adapter) + drizzle d1
packages/shared/ pure types and logic
```

## Scaffold

```sh
{{PM}} create cloudflare@latest apps/api -- --type hello-world --lang ts
{{PM}} create vite apps/web --template react-ts
```

## Rules

- The API is Hono with `hc<AppType>` on the client, which gives the same end-to-end typing as Eden. Use Elysia instead only if its Workers adapter covers what you need, and record that choice in an ADR.
- Write the schema with Drizzle and `drizzle-orm/d1`. Migrations go through `wrangler d1 migrations`, generated by `drizzle-kit`.
- Put bindings (`DB`, `BUCKET`) in `wrangler.jsonc`, and get their types from `wrangler types`, never by hand.
- R2 uploads go through presigned URLs or a Worker route, and the bucket is never public by default.
- Local dev runs `wrangler dev` next to Vite, and Vite proxies `/api`. Plain Vite doesn't run Workers.
- Keep separate `staging` and `production` envs in `wrangler.jsonc`. Deploy is a manual CLI command.
